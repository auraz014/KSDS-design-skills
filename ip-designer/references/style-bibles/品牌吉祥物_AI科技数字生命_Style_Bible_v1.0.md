# 品牌吉祥物 · AI 科技数字生命 Style Bible v1.0

## 1. 子风格定位

本 Style Bible 来自用户提供的 40 张 AI 科技类 IP 参考图：原有 28 张，加上 2026-07-29 新增且去重后的 12 张。它不是独立顶级类别，而是“品牌吉祥物”下的一个子风格，适用于：

- AI 助手与多模态助手
- Agent 与工作流伙伴
- 智能硬件陪伴角色
- 语音、阅读、搜索与内容生成产品
- 系统状态、设备反馈与数字服务人格

核心目标是：

> 将抽象的计算能力转译为一个柔软、轻盈、亲近、可感知状态变化的数字生命。

它继承品牌吉祥物对识别度、亲和力、商业延展与简化表达的要求，但通过材质、光色、运动感和非机械化生命形态表达 AI 时代感。

## 2. 样本观察结论

40 张图片呈现出以下稳定共性：

- 几乎全部使用圆润、连续、低攻击性的体量。
- 大多数角色以一个主要体块承载身体、脸和人格，结构阅读速度很快。
- 科技感高频来自半透明、乳浊、凝胶、柔光、内部渐变和悬浮感，而非金属机械结构。
- 蓝、青、紫、粉构成高频色域，但黄、绿、珊瑚橙同样可以成立。
- 五官普遍精简为少量图形符号；有眼白的大眼只是次要分支，不是唯一答案。
- 角色常通过漂浮、压缩、拉伸、流动或光色变化表现“活着”和“正在响应”。

样本中也包含少量不同材质和形态，用于扩充边界：

- 柔软短绒或雾面表面
- 简化动物原型
- 紧凑软体人形
- 无传统五官的环境型形态只作为透明度、内部光色、颗粒和雾化材质参考，不作为角色造型分支
- 以镜头、传感器、面窗等单一功能器官建立识别的软体设备角色
- 低频出现的细长、连续、无关节图形化肢体
- 透明外壳与内部核心构成的统一双层材质
- 耳机、投影底座、帽子等单一功能性配件

这些是可选变化，不应被平均成每个角色都必须具备的元素。

## 3. 审美核心

### 3.1 温暖未来感

优先表达“聪明但不冷漠”“先进但容易接近”。视觉上避免把 AI 等同于硬件、机甲或赛博装甲。

科技感应主要由以下组合产生：

- 有体积的光
- 材质内部的颜色迁移
- 柔软连续的表面
- 轻微失重或悬浮
- 像界面符号一样简洁的脸
- 可通过颜色与形变反馈状态的身体

### 3.2 低认知负担

角色应该在很小尺寸下仍然成立。第一眼先读到一个完整生命体，第二眼再发现材质、内部光或局部记忆点。

不要依赖复杂结构、服装、机械零件或大量装饰来证明它是 AI。

### 3.3 非机械的数字生命

“数字生命”可以没有现实物种，也可以借用动物或人的少量识别线索。它不需要解释完整生物学结构。

角色的可信度来自一致的形态逻辑与状态反馈，而不是写实解剖。

## 4. 造型生成逻辑

本子风格不把外形限定为某一种几何形。应从角色功能和人格出发，在以下形态家族中自由选择、组合或发展：

### 4.1 有机数据团

- 云团、液滴、软泡、果冻、语音波形或不规则细胞状体块
- 轮廓由 2–5 个柔和起伏构成
- 可以无明显四肢，以漂浮、倾斜和形变完成动作
- 适合通用 Agent、内容生成、云端服务与无实体产品

### 4.2 光核容器

- 圆球、胶囊、豆形、软壳或气囊体
- 外层是柔软半透明容器，内部存在光核、面窗或颜色状态区
- 可以通过内部亮度和色彩变化表达工作状态
- 适合语音助手、智能音箱、硬件中控与设备伙伴

### 4.3 软体小助手

- 紧凑的头身一体或短身人形
- 手脚短小、融合或局部出现，不使用真实人体关节
- 面部可以位于柔光面窗或一块安静的色域中
- 适合办公助手、任务 Agent 与需要动作演示的产品

### 4.4 数字动物

- 保留 2–3 个物种识别线索，例如耳朵、尾巴、喙、触角或身体姿态
- 用软体体积、内部光色和简化肢体将其转译为数字生命
- 不沿用写实宠物比例，不添加真实毛发与关节细节
- 适合需要情感陪伴、硬件人格或品牌故事的产品

### 4.5 软体功能设备

- 从镜头、传感器、扬声器、面窗或输入输出部件中选择一个主要功能焦点
- 保持外壳柔软、结构简化，不堆叠按键、关节、金属件和硬件纹理
- 肢体通常短小或融合；只有少量概念在角色职责和轮廓确实需要时，才使用一对细长、连续、无关节的图形化肢体
- 适合办公 Agent、拍摄识别、智能硬件和需要明确职责的角色

### 4.6 形态选择原则

- 每个角色只需要一个主结构逻辑。
- 轮廓中保留一个可描述的一级记忆点，例如凹口、软角、顶部小冠、侧向鼓包、光核或独特尾端。
- 不要同时叠加云朵、液滴、机器人、动物、宇航员等多套隐喻。
- 多方案生成时，不复用同一“渐变团块 + 豆豆眼 + 短手”的组合。
- 不生成完全无脸的角色；单镜头或非标准状态窗可以作为低频脸部方案，不为多样性机械塞进每一组。
- 长肢体属于低频例外，不设置固定配额，也不默认出现在每组三方案中。
- 形态家族用于打开可能性，不绑定固定方案编号，也不要求每一组机械覆盖全部家族。

## 5. 比例与轮廓

- 以一个主要体块占据角色大部分面积。
- 整体偏紧凑、短宽或饱满；纵向角色也要保持柔软和稳定。
- 四肢缺省为无、隐藏、融合或极短；只有动作和功能确实需要时才出现。
- 低频的功能型角色可使用细长、连续、无关节的手脚，形成图形化长短反差；这不是写实人形许可。
- 脸通常嵌入主体，不强制区分头和身体。
- 外轮廓应能在剪影中识别，且不依赖内部渐变才能成立。
- 允许轻微不对称、倾斜和局部鼓起，让角色像有呼吸，而不是完美几何模型。

## 6. 材质系统

### 6.1 高频材质

- 半透明软凝胶
- 乳浊玻璃或磨砂树脂
- 柔软硅胶
- 充气软膜或气囊
- 带次表面散射的软塑体

这些材质的共同点是：轮廓柔和、内部有体积、光可以进入角色而不是只停留在表面。

### 6.2 光色表现

- 使用边缘透光、内部柔光、局部色雾和缓慢的颜色迁移。
- 高光应帮助说明体积和材质，面积克制、边缘柔软。
- 身体可以有高光，但眼睛继续遵守品牌吉祥物的无高光规则。
- 避免把角色做成过亮的玻璃球、廉价亮塑料或全身镜面反射。

### 6.3 可选材质

- 柔短绒、雾面软胶或粉感表面可用于更陪伴、更生活化的方向。
- 单色实体软材质可用于需要高识别度或小尺寸图标的方向。
- 透明或乳浊外壳与一个内部光核可以组成统一的双层材质系统，层次服务于状态表达，而不是随机混材质。
- 可使用克制的发光颗粒、色雾或云状内部体积表现计算活动，但外轮廓必须保持干净。
- 无脸参考图只用于学习以上透明度、内部光、颗粒、色雾和软体边缘，不把其无脸外形转化为角色方案。
- 可选材质不应在同一角色上与半透明、金属、毛绒、玻璃全部混用。

## 7. 色彩系统

### 7.1 高频色域

- 蓝与青：清晰、连接、响应、云端感
- 紫与粉：想象力、生成感、情绪与亲和力
- 白与乳白：轻、干净、智能、硬件友好

### 7.2 有效扩展色

- 黄与暖橙：活力、创造、积极反馈
- 绿色：生长、完成、可靠状态
- 珊瑚红：温度、提醒与社交性

### 7.3 配色方法

- 单个角色优先使用一个主色域和一个邻近或互补的内部光色。
- 渐变应像发生在材质内部，而不是把彩虹贴在表面。
- 通常控制在 2–3 个主要色相；只有概念需要时才扩大色域。
- 多方案不应全部默认蓝紫渐变。应根据产品人格、功能和品牌色选择颜色。
- 纯色、乳白和明亮暖色也属于本子风格，不应被排除。
- 近白、透明或单色主体配一个集中的内部状态色，同样可以形成克制的科技感。

## 8. 五官与情绪

- 每个正式角色都要有清楚可识别的五官或脸部焦点，通常由 2–4 个简洁图形构成，像界面状态符号一样清楚。
- 优先使用无眼白的点、短条、弧线、竖胶囊、闭眼线和几何眨眼。
- 有眼白的大眼可以用于更强烈的喜剧感、好奇感或动物识别，但应作为次要分支。
- 使用一对传统眼睛的角色继承品牌吉祥物的标准五官 ID 与持久化记录；参考最近 8 个已接受的传统双眼角色维持约 65% 无眼白、35% 有眼白的长期倾向，不要求每组三方案固定为 2:1，也不因近期用过就排除最适合角色的五官。低频的单镜头或非标准状态窗脸部不计入该比例，也不写入五官历史。
- 眼睛不出现高光点、玻璃反射点或水晶眼效果。
- 嘴可以缺省；说话、确认、惊讶和思考状态可通过小弧线、短横、O 形或图形符号表达。
- 可低频使用单镜头或非标准状态窗作为脸部焦点，并通过朝向、亮度、形变和动作完成情绪表达；不使用完全无脸或仅有光核的角色。
- 表情变化应与身体压缩、倾斜、光色或局部形变协同，不只替换嘴型。
- 同一批方案使用不同的标准眼型 ID 与完整脸部签名，并遵守父风格的组内高频池上限；跨会话记录只调整优先级，避免无理由地全部回到豆豆眼、胶囊眼或普通圆眼白。

## 9. 动态与生命感

数字生命的动作不必依赖完整手脚。优先使用：

- 轻微悬浮与上下呼吸
- 软体压缩、回弹和拉伸
- 局部波动、鼓起或收缩
- 颜色从核心向外扩散
- 光核明灭、面窗切换或状态区变化
- 耳朵、触角、尾端或小手的简化响应

动作应让用户感受到“正在听”“正在想”“已完成”“需要帮助”，而不是只做通用卖萌动作。

## 10. 记忆点与细节

每个角色只选择一个主要记忆点，必要时增加一个辅助点：

- 独特的轮廓凹口或软角
- 一块稳定的面窗
- 内部光核或状态带
- 顶部小冠、天线或耳状凸起
- 语音波形、投影底座或耳机等单一功能符号
- 单一镜头、传感器、状态窗或内部光核
- 一处与品牌标志相关的负形或切口

细节必须承担身份或功能，不使用无意义的科技线、发光电路、随机星星和漂浮 UI 碎片。

## 11. 商业应用转译

### AI 助手与 Agent

- 用光色和形变区分待机、聆听、思考、执行、完成与出错。
- 角色需要在头像、对话气泡、加载状态和全身形象之间保持一致。
- 办公、演示或语音场景可在应用图中加入一个笔记本、麦克风或交互对象验证职责，但角色脱离道具后仍须成立。

### 智能硬件

- 可通过投影底座、面窗、灯带或休眠姿态与设备状态对应。
- 结构要能转化为实体软胶、公仔、桌面摆件或硬件屏幕动画。

### 产品界面

- 小尺寸优先保留轮廓、脸和一个状态色。
- 动画延展优先使用呼吸、漂浮、弹性形变和光色变化，避免复杂骨骼动画。

### 品牌传播

- 主视觉可以强化材质与内部色光。
- 表情包、贴纸和运营插图应适当减少透明层级，保证阅读与生产稳定性。

## 12. 面向真实 AI 产品的专业补充

参考图库主要说明“长什么样”，但一个成熟的 AI 数字生命还必须说明“如何工作、如何反馈、如何建立信任”。以下规则是基于产品体验与品牌设计的专业补充，不冒充为 40 张图库中的直接统计结论。

### 12.1 从静态角色升级为状态系统

角色至少要能解释以下状态：

- 待机
- 唤醒或聆听
- 理解输入
- 思考或生成
- 执行动作
- 完成与确认
- 不确定或需要补充信息
- 出错
- 恢复或重试

每个状态应由同一套视觉语法表达，例如：

- 光从外向内收束代表接收
- 光从核心向外扩散代表输出
- 缓慢呼吸代表待机
- 有方向的流动代表处理路径
- 短促、清晰的形变代表确认
- 降低亮度并保持稳定轮廓代表错误或等待，而不是夸张哭泣

不要只准备“开心、难过、生气”的通用表情包。AI 角色最重要的情绪，是让用户理解系统此刻正在做什么。

### 12.2 动效是人格，不是装饰

- 每段动效都要有明确起点、过程和结束。
- 动作速度、幅度、缓动和停顿共同定义角色性格。
- 思考过程可以有内部活动，但不能让用户误以为任务已经完成。
- 成功反馈应短而确定；等待反馈应平静、不催促。
- 为减少动态效果的环境准备静态关键帧，不让语义依赖动画才能理解。

### 12.3 明确它是 AI，而不是假装成人

- 角色可以有情绪和陪伴感，但应保持符号化、非写实和非真人化。
- 不用写实人脸、真人姓名、性别刻板印象或过强的人类身份暗示制造信任。
- 对工作型 Agent，应让角色名称、轮廓或功能符号能说明其职责。
- 不确定、失败或需要确认时，角色要清楚表达边界，不能用过度自信的微笑掩盖问题。

### 12.4 跨设备与跨模态

一个 AI 数字生命可能同时出现在手机、桌面、耳机、音箱、车载和智能硬件中。设计时应准备：

- 完整 3D/2D 主形象
- 小尺寸头像或轮廓标记
- 只保留眼睛、光核或状态带的微型版本
- 默认提案图使用接近白色、第一眼读作白底的极浅中性灰背景，视觉明度可参考 `#F7F8F8`，阴影只保留到几乎不可察觉；避免奶油黄、米黄、象牙白、暖黄、脏灰和明显偏深的灰底
- 白色或浅色角色需要分离时，只轻微加深近白中性灰，不用暖色衬底，也不改成明显灰底
- 产品适配阶段可另备深色背景版本，但只有用户或应用场景明确要求时才启用
- 低透明度、纯色和单色生产版本
- 动效关闭时仍可识别的静态版本

视觉不能承载唯一的关键信息。涉及确认、错误和风险的状态，应同时有文字、声音或界面反馈。

### 12.5 可适应，但不能失去身份

允许角色根据用户、任务或设备改变：

- 状态色
- 内部纹理
- 一处功能性配件
- 光核图案
- 轻微形态张力

必须保持：

- 主轮廓逻辑
- 脸部语法
- 一级记忆点
- 核心动作节奏

个性化发生在“可变层”，身份建立在“恒定层”。

### 12.6 信任与克制

- 角色不应持续抢占注意力。
- 办公型 Agent 的默认状态应安静、可靠，只有需要用户行动时才提高动作和色彩强度。
- 错误状态不使用卖惨、哭泣或愧疚表演迫使用户安慰角色。
- 涉及删除、支付、发送或公开发布等重要动作时，角色的确认状态应与普通成功反馈明显区分。
- 视觉愉悦不能替代清晰、可撤销和可恢复的产品反馈。

### 12.7 专业补充依据

这些补充参考了近期一手产品设计指导中的共同原则：

- [Google Design：Gemini AI Visual Design](https://design.google/library/gemini-ai-visual-design) 强调内部活动、方向性渐变和有意图的运动，用以说明思考、输入与输出。
- [Apple Human Interface Guidelines：Generative AI](https://developer.apple.com/design/human-interface-guidelines/generative-ai/) 强调生成期间的具体反馈、错误说明、用户控制和真正有差异的备选结果。
- [Microsoft Design：Responsible Agent Design](https://microsoft.design/articles/principles-for-responsible-agent-design/) 强调 Agent 与真人的视觉区分、明确职责和避免误导性人格化。
- [Microsoft Design：When Outputs Are the Experience](https://microsoft.design/articles/when-outputs-are-the-experience/) 将平静、克制、有节奏的动效视为建立信任的一部分。
- [Apple Human Interface Guidelines：Siri](https://developer.apple.com/design/human-interface-guidelines/siri/) 强调跨设备、跨视觉与语音情境的一致反馈。

这些来源只用于补足产品行为原则，不作为模仿任何具体品牌视觉的依据。

## 13. 多方案差异控制

生成多个方向时，先为每个方向确定独立的：

- 产品角色隐喻
- 主轮廓逻辑
- 材质机制
- 面部语法
- 状态反馈方式
- 一级记忆点

不要预设固定顺序，也不要每次都按“第一个圆球、第二个云团、第三个小机器人”的套路排列。

多方案之间可以共享同一审美，但不能只更换颜色、耳朵或渐变位置。若两个方案的主体轮廓、脸、材质和姿态同时相似，应重新设计其中一个。

## 14. 避免方向

- 硬表面机甲、机器人盔甲、外露关节和复杂机械零件
- 用电路板、芯片纹理、HUD 和霓虹线条堆砌科技感
- 写实人类身体、真实宠物比例或复杂动物解剖
- 每个方案都是同一种圆润渐变果冻团
- 把无脸渐变团、单纯光核或环境型体块直接当成完整角色
- 全部方案默认蓝紫粉彩虹渐变
- 高亮水晶眼、眼睛反光点和过度玻璃质感
- 过强镜面、廉价亮塑料、材质不一致或边缘融化
- 多套服装、无功能配件或复杂宇航员造型
- 过量光晕导致轮廓和五官失去清晰度
- 写实人脸、真人化身份或让用户误以为正在与真人互动
- 用持续跳动、夸张卖萌或高强度动画抢占用户注意力
- 用哭泣、愧疚或卖惨表达系统错误
- 只有好看但无法区分待机、思考、执行、确认与失败状态
- 动效关闭、透明度降低或缩小后就失去识别度
- 直接复刻样本中的角色轮廓、面孔、标志或品牌资产

## 15. Prompt 组装顺序

建议按以下顺序构建生成描述：

1. 产品角色与功能
2. 数字生命隐喻与人格
3. 主体轮廓和一级记忆点
4. 比例与肢体处理
5. 五官或功能焦点与当前状态
6. 材质及内部光色机制
7. 主色域与辅助色
8. 动作、悬浮或形变
9. 状态反馈与动效逻辑
10. 跨设备、缩小和静态降级方式
11. AI 身份与信任提示
12. 使用场景和画面规格
13. 独立的负面约束

不要直接使用参考案例的角色名、品牌名或作品名作为生成指令。

## 16. 生成质量门槛

在交付前检查：

- 第一眼是否像具有生命感的品牌角色，而不是材质测试球。
- 科技感是否来自材质、光、状态和动作，而非机械装饰。
- 轮廓在去掉渐变后是否仍有识别度。
- 五官是否清晰、有意图且没有眼睛高光。
- 如果使用低频的单镜头或状态窗脸部，功能焦点、朝向和状态行为是否仍然清楚。
- 材质是否统一，边缘是否干净，没有无意义融化。
- 多个方向是否真正改变角色逻辑，而不是同一果冻模板的换色。
- 是否适合头像、界面状态、动画和实体周边至少三类延展。
- 是否能清楚区分聆听、思考、执行、完成、不确定和错误。
- 动效关闭、切换深浅背景或缩至图标后是否仍然成立。
- 是否明确保持 AI 的符号身份，没有伪装成真人。
- 是否避开对任何单一参考角色的近似复制。
